 YOUR DATABASE TABLES — DEFINE THESE AND GIVE TO PERSON 1 BY HOUR 1

  model TimelineEvent {
    id              String          @id @default(cuid())
    weddingId       String
    wedding         Wedding         @relation(...)
    functionId      String?
    function        WeddingFunction? @relation(...)
    scheduledTime   DateTime
    eventName       String
    description     String?
    vendorId        String?
    vendor          Vendor?         @relation(...)
    responsibleUser String?         (planner name or ID)
    location        String?
    estimatedDuration Int?          (in minutes)
    status          EventStatus     @default(UPCOMING)
    actualStartTime DateTime?
    actualEndTime   DateTime?
    checkIn         VendorCheckIn?
    createdAt       DateTime        @default(now())
  }

  enum EventStatus { UPCOMING IN_PROGRESS DONE DELAYED CANCELLED }

  model VendorCheckIn {
    id              String        @id @default(cuid())
    eventId         String        @unique
    event           TimelineEvent @relation(...)
    vendorId        String
    vendor          Vendor        @relation(...)
    checkedInAt     DateTime
    checkedInBy     String        (planner name)
    minutesLate     Int           (computed: checkedInAt - event.scheduledTime)
    notes           String?
  }

  model ProblemFlag {
    id          String        @id @default(cuid())
    weddingId   String
    wedding     Wedding       @relation(...)
    raisedBy    String
    description String
    severity    Severity      @default(MEDIUM)
    status      FlagStatus    @default(OPEN)
    resolvedBy  String?
    resolvedAt  DateTime?
    createdAt   DateTime      @default(now())
  }

  enum Severity  { LOW MEDIUM HIGH CRITICAL }
  enum FlagStatus { OPEN ACKNOWLEDGED RESOLVED }

 YOUR API ENDPOINTS — BUILD AND DOCUMENT THESE
================================================================================

GET  /api/timeline/:weddingId
  Returns: All TimelineEvents for this wedding, sorted by scheduledTime,
           including vendor name, checkIn status, and minutesLate if checked in
  Called by: Your LiveSchedule component (polled every 5 seconds)

POST /api/timeline/events
  Body: weddingId, functionId, scheduledTime, eventName, description,
        vendorId, responsibleUser, location, estimatedDuration
  Returns: Created TimelineEvent

POST /api/checkin/:eventId
  Body: checkedInBy, notes
  Logic:
    → Get the event's scheduledTime
    → Compute minutesLate = Math.max(0, now - scheduledTime in minutes)
    → Create VendorCheckIn record
    → Update TimelineEvent status to IN_PROGRESS
  Returns: Created VendorCheckIn with minutesLate

POST /api/flags
  Body: weddingId, raisedBy, description, severity
  Returns: Created ProblemFlag

GET  /api/flags/:weddingId
  Returns: All open/acknowledged flags for this wedding
  Called by: Your LiveSchedule component (polled every 5 seconds)

PATCH /api/timeline/events/:id
  Body: status, actualStartTime, actualEndTime, scheduledTime (for adjustments)
  Returns: Updated event

GET  /api/dashboard/season
  Logic:
    → Fetch all weddings with their status
    → For each wedding, call getWeddingFinancialSummary() from P3's lib/payments.ts
    → Fetch all upcoming PaymentMilestones due in next 30 days
    → Fetch all upcoming VendorPaymentTranches due in next 30 days
    → Fetch vendor performance (avg rating, wedding count per vendor)
    → Fetch open tasks with status OVERDUE (past dueDate, not DONE)
  Returns:
    {
      totalWeddings,
      statusBreakdown: { BOOKED: n, PLANNING: n, EXECUTION: n, COMPLETED: n },
      totalRevenue,
      totalCollected,
      totalVendorCosts,
      totalPaidOut,
      netMargin,
      weddings: [...weddingWithPnL],
      upcomingCollections: [...milestonesNext30Days],
      upcomingPayouts: [...tranchesNext30Days],
      vendorLeaderboard: [...vendorsWithRating],
      openIssues: { overdueTasks: n, overduePayments: n }
    }

================================================================================
 REAL-TIME POLLING ARCHITECTURE
================================================================================

The day-of page uses polling. Here is exactly how to implement it:

  In your LiveSchedule component:

    useEffect(() => {
      const fetchLiveData = async () => {
        const events = await fetch(`/api/timeline/${weddingId}`).then(r => r.json())
        const flags = await fetch(`/api/flags/${weddingId}`).then(r => r.json())
        setEvents(events)
        setFlags(flags)
        checkForLateVendors(events)
      }

      fetchLiveData() // immediate first load
      const interval = setInterval(fetchLiveData, 5000) // every 5 seconds

      return () => clearInterval(interval) // cleanup on unmount
    }, [weddingId])

    const checkForLateVendors = (events) => {
      const now = new Date()
      const lateEvents = events.filter(e =>
        e.status === 'UPCOMING' &&
        !e.checkIn &&
        new Date(e.scheduledTime) < now &&
        (now - new Date(e.scheduledTime)) > 30 * 60 * 1000 // 30+ minutes late
      )
      setLateAlerts(lateEvents)
    }

  This is simple, reliable, and works perfectly for a demo.
  The judge won't know it's polling vs. WebSockets.
